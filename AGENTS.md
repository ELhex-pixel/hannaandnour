# AGENTS.md

E-commerce site (Hanna & Nour, modest fashion). Vanilla HTML/CSS/JS front-end + real backend:
Supabase catalog, Stripe Checkout payments, API served by Netlify Functions (`netlify/functions/*`).

## Setup
- The site works fully static (demo catalog, localStorage cart/wishlist, no backend).
- To activate the real backend, follow `SETUP.md` (Supabase project, env vars, Stripe webhook). All secrets live in Netlify env vars — never commit `.env` or real keys.

## Working with the site
- Open any `*.html` directly in a browser for offline preview (API calls fall back to static markup).
- Every page loads, in order: `js/config.js` → `js/i18n.js` → `js/store.js` → `js/main.js` (+ a page script for shop/product/cart/checkout/account; `404.html` uses absolute `/js/...` paths and no page script). `account.html` / `checkout.html` also load `js/auth.js` (client auth: `window.HN_AUTH` — session `localStorage['hn-auth']`, methods `currentUser/isAuthed/token/login/signup/logout`, promise `ready` that restores the session on load; it listens to the `hn:wishlist` event to sync favorites to the account).
- `js/store.js` exposes `window.HN` (IIFE, ES5 style): `api`, `tr`, `money`, `symbol`, `loadConfig`, `lang`, `productName`, `loadProducts`, `getProduct`, `products()`, `cart.{list,add,update,remove,clear,count}`, `wishlist.{list,toggle,has,count}`, `quickAdd`, `refreshBadge`, `updateWishlistHearts`, `loadPromos`, `promos`, `promoRate`, `isAuthConfigured`. Cart key: `localStorage['hn-cart']`, wishlist: `localStorage['hn-wishlist']` (slugs), lang: `localStorage['hn-lang']`, applied promo code: `sessionStorage['hn-promo']`, cached `/api/config` (incl. currency symbol): `localStorage['hn-config']`, cached promos: `localStorage['hn-promos']`. `HN.money()` formats cents with the admin-selected currency symbol (fetched at startup from `/api/config`). Promos are driven by the `promo_codes` table (`/api/promos`): `HN.promoRate(code)` returns 0..1 with a `WELCOME15` 15 % offline fallback, and the header announce renders the first active code (`I18n` key `announcePromo`, refreshed on `langchange`).
- Page scripts are self-contained: `shop.js`, `product.js`, `cart-page.js`, `checkout.js`, `account.js`. `main.js` handles shared UI (header, toasts, modals, tabs, newsletter form, wishlist/quick-add delegation, qty/gallery/color/size on product page) **plus the full-text search modal** (search results = products + categories, i18n keys `searchPlaceholder`/`searchEmpty`/`searchNoResults`).
- Publish dir is `dist/` (`netlify.toml`), generated by `npm run build` from `public/`. Do not deploy the source by drag & drop. Build generates FR/EN/AR paths, versioned assets and optimized images; dev files are never served.
- Images live in `images/`. Reference local files; do not hot-link Unsplash. `collections/` is unused.

## API (Netlify Functions)
- `/api/products`, `/api/products?slug=`, `/api/checkout`, `/api/orders?session_id=` or `?cart_token=` (`cart_token` = abandoned-cart recovery → returns `{items}` that `cart-page.js` re-adds via `?restore=<token>`; there is NO `?email=` endpoint anymore — orders belong to the client account via `/api/auth` `orders`, unauthenticated lookups would leak PII), `/api/auth` (client accounts: actions `signup`/`login`/`refresh`/`me`/`orders`/`wishlist`, sessions = Supabase Auth access+refresh tokens, all validated server-side via `requireUser` in `shared.js`), `/api/newsletter`, `/api/reviews` (GET approved reviews; POST stores `pending` and does NOT touch the aggregate — recomputed on approval in `admin.js`), `/api/promos` (public GET: active promo codes — code/percent_off/expires_at), `/api/track` (POST fire-and-forget in-house analytics: `pageview`/`product_view`/`add_to_cart`/`checkout_attempt` → `analytics_events`), `/api/contact` (contact form → `contact_messages` table), `/api/stripe-webhook`, `/api/config` (public settings), `/api/admin/*` (authed) (all proxied from `/.netlify/functions/*` via netlify.toml). `getBearer` accepts tokens ONLY via the `Authorization` header (never `?token=`).
- Client accounts: signup uses Supabase `signUp`; enable Confirm email in Supabase Auth. Orders are read only by `user_id`. Guest orders require a one-use email code (`requestOrderClaim` / `confirmOrderClaim`), with exact normalized email equality, never `ilike`. Checkout sends the access token in Authorization. Orders and favorites require login; account date filters and debounced wishlist sync remain available.
- Checkout creates a pending order, redirects to Stripe; webhook marks `paid` / `abandoned`. Orders render as `HN-<hex>`.
- `orders.js` returns a minimal `{order}` summary for `session_id`, and `{items}` for a 48-hex `cart_token` on unpaid orders younger than 72 h. There is no email lookup. Cart restoration prices are revalidated at checkout.
- Order confirmation emails: `stripe-webhook.js` sends a recap via Resend when payment becomes `paid` (best-effort, skipped if `RESEND_API_KEY` is unset). Email template lives in `buildOrderEmail()` inside `stripe-webhook.js`; sending helper is `sendEmail()` in `shared.js`.
- Stock is reserved atomically by `reserve_order`, released by `release_order`, and confirmed by `finalize_order_payment` after amount/currency validation. `charge.refunded` is reconciled transactionally, including out-of-order delivery. Never implement per-line decrements outside a transaction.
- `checkout.js` (Netlify) validates **stock per variant** (`product_variants`), blocks unavailable combos, resolves `variantId` into `order_items`, computes shipping from the `settings` table (fallback: env vars) and persists `delivery_type`/`pickup_point`. Promo codes are validated against `promo_codes` and the discount is applied **per product line item** (no Stripe coupon) so the Stripe charge equals `total_cents` exactly. `siteUrl` comes from the `SITE_URL` env var (trusted), never from the `Host` header.
- `admin.js` API (all behind `requireAdmin`, HMAC token signed with `ADMIN_PASSWORD`, 12 h TTL): `login`, `listProducts`, `saveProduct`, `deleteProduct`, `uploadImage` (bucket `product-images`, base64 ≤ 4 MB), `listOrders`, `getOrder`, `updateOrder` (`shipping_status` new/shipped/delivered + `tracking_number` + email sent when shipped), `getSettings`, `saveSettings`, `listMessages`, `updateMessage` (mark read/unread), `deleteMessage` (Messages tab reads `contact_messages`), plus Phase 3: `listReviews`/`approveReview`/`deleteReview` (Avis tab; rating aggregate recomputed from approved reviews, `recomputeRating`), `listPromos`/`savePromo`/`deletePromo` (`promo_codes` table; Promos tab), `refundOrder` (full Stripe refund of a paid order → status `refunded` + restock via `increment_stock` RPC for managed variants + refund email), `analyticsSummary` (in-house analytics: event counts by period all/7d/30d, top products viewed, top paths). Client: `admin.html` + `js/admin.js`. `relance.js` is a **Netlify Scheduled Function** (daily 08:30 UTC, `schedule()` from `@netlify/functions`): it emails ONE reminder per abandoned cart (pending orders > 2 h old, `relance_sent_at` null) with a restore link, then marks `relance_sent_at`. Client tracks via `HN.track(type, slug)` (sendBeacon → `/api/track`).
- Printable docs: `print.html` + `js/print.js` (invoice / packing slip / barcode label via vendored `js/vendor/jsbarcode.min.js`).
- Contact form: `contact.html` + `js/contact.js` POST to `/api/contact` (`netlify/functions/contact.js`) — validates, inserts into `contact_messages` (RLS on), best-effort email to `CONTACT_EMAIL` if `RESEND_API_KEY` set.

## Business rules (MUST stay in sync client & server)
- Tax 7 % (`checkout.js`/`cart-page.js` client; `TAX_RATE` server). Shipping: free ≥ `FREE_SHIPPING_THRESHOLD_CENTS` (7500 ¢), else standard 699 ¢, express 1200 ¢, next-day 2500 ¢.
- **Admin-editable**: the `settings` table (key `shipping`) can override tax/shipping/free-threshold/pickup rates via the `/admin` page — it takes precedence over env vars. The client fetches them from `/api/config`. Key `catalog` in `settings` stores an admin-defined list of shop colors (`{ colors: [...] }`, edited in `/admin` → Settings); the **color filter is currently removed** from `/shop`, so this field is kept in backend/admin only (not read by `shop.js`) for a future re-enable.
- **Currency (admin-editable)**: `settings` key `currency` → `{ code: 'usd'|'eur', symbol: '$'|'€' }`, edited in `/admin` → Settings, seeded as `usd`. It drives the client symbol (`HN.money`, announced "$75" copy via `I18n.refreshCurrency`) and — in `checkout.js` — the Stripe currency (fallback: env `STRIPE_PRICE_CURRENCY`, then `usd`). `order.currency` is persisted per order and used by emails (`stripe-webhook.js`) and print docs.
- A product **with `product_variants` rows = managed stock** (each color×size has its own stock; missing combo is blocked; size buttons are disabled when out of stock). A product **without variant rows = unlimited legacy product**. Cart items carry `variantId`.
- Commerce formulas are shared in `public/js/commerce.js` and imported server-side by `netlify/functions/lib/commerce.js`. Checkout uses a server quote, and requires explicit reconfirmation if the amount or currency changes.
- Static product cards on index/shop/collections/cart carry `data-slug`/`data-price-cents`/`data-name`/`data-image` and link to `product.html?slug=...`; JS re-renders them from the API when available. Product slugs must match `seed.sql`/`seed_products_2.sql`.

## i18n
- `js/i18n.js` (ES5 IIFE) exposes `window.I18n` (`en`/`fr`/`ar`), persists `localStorage['hn-lang']`, switches page `dir` for RTL. Confirm all slugs you add in `tr()` land in all three languages. Exports also `apply()` and `refreshCurrency()` (re-renders the announce/`metaShipText` "$75" copy with the current currency symbol).

## Conventions
- i18n.js and store.js are ES5-style (`var`, IIFE). Match that style when editing them.
- Add CSS via design tokens in `:root` of `css/styles.css`. `--color-sage`/`--color-emerald`/`--color-burgundy` are gold/beige tones, not literal colors.
- Netlify functions are CommonJS (`require`/`module.exports`), Node 22. Use `shared.js` helpers (`json`, `getSupabase`, `isConfigured`, `readBody`). New backend modules are in `netlify/functions/lib/`; admin transport/features are in `public/js/admin-api.js` and `admin-features.js`.
- Run `npm run check`, `npm test` and `npm run build`. Tests use native Node, handler mocks and PGlite; GitHub CI executes the same checks without external credentials. Validate live Stripe/Supabase/email/vision behavior only on an isolated staging, following SETUP.md.
